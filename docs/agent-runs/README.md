# Agent-run packets — conventions

Packets are how the PIIA pilot crosses from this repo (the verification bench) to the FEMA-side build machine. The approach is the one used on the Boss project (`seanyofthedead/boss_project`, `docs/agent-runs/CICD-19-*.txt`); the rules below are lifted from those packets so that an operator who has run one can run these without re-learning anything. Design context: `solution-design/fema-program-id-risk-assessment/18-databricks-implementation-plan.md` §3a.

## Kinds

| Kind | Writes? | Example |
|---|---|---|
| **Recon** | Only the STEP-RESULT file | `PIIA-01-gfe-recon.txt` |
| **Recon + guarded write** | One write step, refuse-by-default, gated on `$ready` from the recon step in the same window | `PIIA-02-gitlab-project.txt` (planned) |
| **Payload** | Text files into the local git clone, each verified by SHA-256, then commit and push | `PIIA-03-payload-engine-v0.txt` (planned; generated by `tools/make_packet.py`) |
| **Addendum** | Whatever its parent allowed; reuses the parent window's variables and refuses if they are missing | `PIIA-0x-step-3b-….txt` |

## File and header

- One plain-text file per run: `docs/agent-runs/<ID>-<slug>.txt`. IDs are `PIIA-NN`; addenda are `PIIA-NN-step-<n><letter>-<slug>`.
- First line: `[agent-run][fema-piia][<ID>][v<n> | STEP <n><letter> addendum]`.
- Sections in this order: `WHY NOW`, `WHAT THIS DOES NOT TOUCH`, `BEFORE YOU START`, `STEP 0` … `STEP n`, `HOW TO READ IT`, `EMAIL BACK`.
- Lines under 72 characters where possible; the operator reads the file in Notepad with **Format > Word Wrap > ON**.

## Blocks

- One PowerShell 5.1 window for the whole packet. Steps hand state to each other in memory; if the window closes, the operator starts again from STEP 0.
- STEP 0 is the preamble: variables, the result file path, `$enc` (UTF-8 without BOM), and the helpers `OUT`, `ERRBODY`, `GETJ`, `GITC`, `UNSEC`, `TOKCHK`, `TOKEN`. Copy them verbatim from the latest packet; do not restyle them.
- Every block sits between `# ----- BEGIN PASTE -----` and `# ----- END PASTE -----` and ends by printing `"STEP n OK"`. The operator pastes one block, presses Enter once, and does not continue without the OK line.
- Blocks are written so a half-paste fails loudly rather than half-runs: no multi-line constructs that could execute a prefix, one statement per line, `$ErrorActionPreference = 'Continue'`.
- The result file is `%USERPROFILE%\STEP-RESULT-<ID>.txt`, written through `OUT` only. The final step is always `notepad $out`.

## Writes

- Read-only recon comes first and sets `$ready` only when every precondition holds; it prints the reason when it does not.
- The write step begins with `$go = ($ready -eq $true -and …)` and prints `STEP n REFUSED - nothing was changed` otherwise. Skipping the write step is the way to decline. Immediately after the write, `$ready = $false`.
- After a write, a verification read follows in the same or the next block (re-read the object, `ls-remote`, `Get-FileHash`).
- Capture error bodies with `ERRBODY`, never just `$_.Exception.Message` (the CICD-19 STEP 4b lesson). Wrap API list results in `@(… | Where-Object { $_ -ne $null })` so an empty list counts as zero (the other STEP 4b lesson).

## Secrets

- Tokens are typed into the masked prompt behind the `TOKEN` command, never pasted into a block, never echoed, never written to the result file. Name them `agent-<purpose>-temp`, scope them minimally, expire them the next day.
- A dedicated revoke step always runs, even if the write step was skipped, and clears `$tok` and `$H`.
- Packets never contain workspace URLs, tokens, real data, or CUI. Hostnames that the operator must supply are entered at a `Read-Host` prompt.

## Payload packets

- Generated by `tools/make_packet.py` from a file list; never hand-assembled.
- One text file per block: a single-quoted here-string, written with `[IO.File]::WriteAllText($path, $s.Replace("`r`n", "`n"), $enc)` so the bytes on disk are UTF-8 with LF, then `Get-FileHash -Algorithm SHA256` compared to the hash computed here on the same LF bytes. The block prints `STEP n OK` only if the hash matches.
- Files longer than about 3,000 lines are split across numbered blocks and concatenated on the GFE before hashing. The generator refuses any file containing a line that begins with `'@`, and any binary.
- The last blocks `git add`, `git commit -m "<ID>: <slug> (source <short commit hash here>)"` and `git push`, then `ls-remote` to prove the push landed.
- Notebooks travel as `.py` source, never `.ipynb`; wheels are never shipped (built on the GFE or from the Repos checkout in FEMADex).

## Return path

- The operator emails back the text of the STEP-RESULT file, not a screenshot or a console copy.
- Result files may contain hostnames, versions, git output and aggregate counts. They must never contain rows of real data; recon steps that touch FEMADex tables print counts only.
